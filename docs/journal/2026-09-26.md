### 앱 목록에 안 보임 — 원인 둘
1. **Exec를 PATH에서 못 찾음**: `Exec=nexa-coffee`인데 gnome-shell PATH(`/usr/local/sbin:…:/snap/bin`)에 `~/.local/bin`이 없다. `~/.profile`은 로그인 시점에 폴더가 **있어야** PATH에 넣는데 첫 설치라 없었다. GLib `GDesktopAppInfo`는 Exec를 못 찾으면 항목을 **숨긴다**. (nexa-clip·nexa-sql은 절대 경로, nexa-beep은 `/usr/bin`이라 멀쩡했다.)

- 수정(`0b1571b`): `install.sh`가 Exec를 `$PREFIX/bin/nexa-coffee`로 치환해 쓰고, 캐시가 **있을 때만** `gtk-update-icon-cache`(실패 시 `touch`) · `update-desktop-database`. `uninstall.sh`도 캐시 갱신. 임시 prefix로 캐시 있음/없음 × 설치/제거 확인. 릴리스 tar.gz 반영은 다음 릴리스부터.

### T-19 — v0.1.1 SIGSEGV(늦게 뜬 워처) 발견·수정 ★
- 가짜 워처를 앱 **뒤에** 띄우자 `GETALL timeout` → 앱 사망. 릴리스 바이너리로 재현: `exit=139`(SIGSEGV).
- 원인: `handle()`의 NameOwnerChanged 분기가 `register_watcher()`를 바로 부른다. 그 신호는 아직 `rbuf` 맨 앞(메인 루프가 `handle` 뒤에 `db_consume`)이라 등록 `db_call`의 `db_recv`가 **같은 신호**를 다시 꺼내 `handle` → `register_watcher` → … 무한 재귀. 매 단계 Register를 보낸다(가짜 워처 로그에 REGISTER 반복).
- 09-13 실기에서 안 보인 이유: 워처가 먼저 있으면 `main()`이 직접 등록한다(핸들러 경유 아님). 실제로 터지는 경우 = 로그인 자동 시작이 셸보다 빠를 때 · GNOME 확장 켜기 · 셸/plasmashell 재시작.
- 수정(`2fa1e8b`): 핸들러는 `need_register = 1`만 · 메인 루프가 세션 버스를 다 비운 뒤 `while (need_register) register_watcher()`.

### T-18 — Windows 대기 중 배율 변경(`e21a4d8`) · 실기는 Windows 필요
