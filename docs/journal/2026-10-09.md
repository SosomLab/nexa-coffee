## 1차 — Linux 패키지 저장소(SosomLab/linux-repo)에 등록

### 요청(사용자)
"nexa-sql 참고해서 linux-repo 배포 진행" → "내용 정리 후 진행사항 최신화 · commit · main 병합 · push".

### 참고한 것
- **`SosomLab/linux-repo`** = 서명된 APT·RPM 저장소(pkg.sosomlab.com · Cloudflare Pages). 앱 등록 = `apps/<pkg>.toml` 한 파일. 패키지 파일은 싣지 않고 색인의 경로를 앱 Release 자산으로 302 보낸다. **최신 정식 릴리스 하나만** 싣는다. `[deb]` 자산이 없으면 발행 **전체**가 실패하고, `[rpm]`은 경고만 남긴다.
- **nexa-sql**: `packaging/linux/build-deb.sh`·`build-rpm.sh`·`nexa-sql.spec`(같은 FHS 스테이징을 deb·rpm이 담음) + `linux-repo.yml`(릴리스 `published` 이벤트 → 자산 확인 → `app-released` dispatch).

### nexa-coffee에 맞춘 설계

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 포장 | `packaging/linux/build-pkgs.sh <바이너리> <버전> <출력>` — **포장만**(빌드 안 함) · control·spec은 스크립트 안 heredoc | 릴리스 tar.gz 안 musl 정적 바이너리를 같은 바이트로 담는다 → 기존 릴리스에도 덧붙일 수 있다 |
| 레이아웃 | `/usr/bin/nexa-coffee` · `/usr/share/applications/nexa-coffee.desktop` · hicolor 64/256 · `/usr/share/doc/nexa-coffee/{LICENSE,copyright}` | FHS · nexa-sql과 같은 꼴 |
| 의존성 | Depends 없음 · Recommends `zenity \| yad \| kdialog`(입력 창 도구) · Suggests `gnome-shell-extension-appindicator` | 정적 바이너리 · 트레이 호스트는 데스크톱 몫 |
| 자산 이름 | `nexa-coffee_<v>_amd64.deb` · `nexa-coffee-<v>-1.x86_64.rpm` | nexa-sql 꼴(Debian·RPM 관례) |
| 실행 시점 | `linux-packages.yml`을 **release.yml이 `workflow_call`**(homebrew·windows-packages와 같은 자리) · 수동 `workflow_dispatch(tag)` = 기존 태그 덧붙이기 | release.yml은 GITHUB_TOKEN으로 공개 → `release: published` 이벤트가 다른 워크플로를 깨우지 않는다(nexa-sql식 이벤트 수신이 안 된다) |
| 자산 규칙 | 이미 있는 이름은 올리지 않고 건너뜀 | "한 번 올린 Release 자산은 지우거나 다시 올리지 않는다"(서명된 색인 해시가 가리킴) |
| 신호 | `LINUX_REPO_DISPATCH_TOKEN`으로 `app-released` · 없으면 알림만(linux-repo 하루 1회 정기 실행이 잡음) | 시크릿은 10-05에 이미 등록돼 있었다 |

- 대상 버전 = **v0.1.2만**. linux-repo는 최신 하나만 싣고, v0.1.0·0.1.1은 T-19(Linux SIGSEGV)가 있어 덧붙이지 않는다.

### 순서(발행 실패 방지)
1. nexa-coffee push → `linux-packages` 수동(tag v0.1.2) → .deb·.rpm 덧붙임 + 신호(이때 linux-repo엔 아직 등록 없음 = 영향 없음).
2. linux-repo `apps/nexa-coffee.toml` push → `publish` 수동 → 실제 색인 확인.

### 사고 · 메모
- 이 Mac의 로컬 main이 원격보다 **수십 커밋 뒤**(v0.1.0 시점)였다 — 첫 push가 non-fast-forward로 거절 → `main`을 `origin/main`으로 맞추고 작업 브랜치를 rebase(README·DEVLOG·STATUS 충돌 정리 · 대상 버전 v0.1.0 → v0.1.2로 고침). 교훈: 작업 시작 전에 `git fetch`.
- 이 Mac엔 dpkg-deb·rpmbuild가 없고 Docker 데몬이 꺼져 있어 `build-pkgs.sh`는 **CI에서 처음 실행**했다.

### 검증
- push 전(rebase 뒤 다시): `make test` green · `make win`(x86 33,280 B) ✓ · `make app` 빌드 ✓ · linux-smoke(맥 네이티브 linux.c 빌드 · 가짜 워처·logind) all green.
- 생략: `scripts/test-install.sh`(GNU `touch -d` — Linux 전용 · CI가 돎) · `make app` 실행 확인(이미 떠 있던 `/Applications` 설치본이 활성화돼 dist 번들은 못 봄 · 소스 무변경).
