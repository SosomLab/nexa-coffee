# 2026-10-09

## 1차 — pkg.sosomlab.com(APT · RPM) 배포 채널 추가 (사용자 요청 "nexa-sql 참고해서 linux-repo 배포 진행")
### 참고한 것
- `SosomLab/linux-repo` = 서명된 APT·RPM 저장소(pkg.sosomlab.com · Cloudflare Pages). 앱 등록 = `apps/<pkg>.toml` 한 파일 · 패키지 파일은 싣지 않고 앱 Release 자산으로 302 · `[deb]` 자산이 없으면 발행 **전체**가 실패, `[rpm]`은 경고만.
- nexa-sql: `packaging/linux/build-deb.sh`·`build-rpm.sh`·`nexa-sql.spec`(같은 FHS 스테이징을 deb·rpm이 담음) + `linux-repo.yml`(릴리스 `published` 이벤트 → 자산 확인 → `app-released` dispatch).
### nexa-coffee에서 달라진 점
- 릴리스(최신 v0.1.2)엔 .deb/.rpm이 없다(tar.gz뿐) → **포장만** 하는 `packaging/linux/build-pkgs.sh <바이너리> <버전> <출력>`(control·spec을 스크립트 안 heredoc으로 · musl 정적이라 Depends 없음 · Recommends `zenity | yad | kdialog` = 입력 창 도구). 레이아웃: `/usr/bin/nexa-coffee` · `.desktop` · hicolor 64/256 · `/usr/share/doc/nexa-coffee/{LICENSE,copyright}`.
- 바이너리 = 릴리스 tar.gz 안의 것 그대로(같은 바이트). 그래서 기존 v0.1.2에도 자산을 **덧붙일** 수 있다(지우거나 다시 올리지 않음 규칙과 충돌 없음 · 이미 있으면 건너뜀).
- 신호 시점: release.yml이 GITHUB_TOKEN으로 공개하므로 `release: published` 이벤트가 다른 워크플로를 깨우지 않는다 → nexa-sql식 이벤트 수신 대신 **`linux-packages.yml`을 release.yml이 `workflow_call`**(homebrew·windows-packages와 같은 자리). 수동 `workflow_dispatch(tag)` = 기존 태그 덧붙이기.
- 자산 이름 = nexa-sql 꼴: `nexa-coffee_<v>_amd64.deb` · `nexa-coffee-<v>-1.x86_64.rpm`. 시크릿 `LINUX_REPO_DISPATCH_TOKEN`은 이미 등록돼 있었다(10-05).
### 순서(발행 실패 방지)
1. nexa-coffee push → `linux-packages` 수동 실행(tag v0.1.2 — linux-repo는 최신 정식 릴리스 하나만 싣고, v0.1.0·0.1.1은 T-19 SIGSEGV가 있어 덧붙이지 않는다) → .deb·.rpm 덧붙임 + 신호(이때 linux-repo엔 아직 등록 없음 = 영향 없음).
2. linux-repo `apps/nexa-coffee.toml` push → `publish` 수동 실행 → 사이트 표·`repo.json`에서 nexa-coffee 확인.
### 검증
- push 전: `make test` green · `make win` ✓ · `make app` 빌드 ✓(실행 확인은 생략 — 소스 변경 없음) · linux-smoke(맥 네이티브 linux.c 빌드) all green.
- build-pkgs.sh는 이 Mac에 dpkg-deb·rpmbuild가 없고 Docker 데몬이 꺼져 있어 **CI에서 처음 실행**(설치 스모크 = `dpkg -i` → 파일 확인 → `dpkg -r`).
