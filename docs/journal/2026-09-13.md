# 2026-09-13 — 메뉴 맨 위 남은 시간(1초 갱신)

## 요청(사용자)
트레이 아이콘 좌클릭 시 맨 위에 `0 day 0 hour 0 minute 0 second` 형식으로 남은 시간을 1초 단위로 갱신, 1보다 크면 복수형.

## 구현
- 코어: `CfApp.remaining_s`(플랫폼이 메뉴 생성 전 채움 · 올림) · `cf_remaining_label` · 루트 맨 위에 `CF_ID_STATUS`(비활성) + 구분선. 복수형 규칙은 문자 그대로 `v > 1` → 0은 "0 day"(사용자 확정 문구). 한국어는 단복수 없음. 무제한 = "무제한 · 절전 방지 중", 대기 = "대기 중".
- macOS: `menuWillOpen:`에서 1초 반복 타이머(common modes — 메뉴 추적 중에도 발화) → `itemWithTag:` 제목 교체 · `menuDidClose:`에서 무효화.
- Windows: `TrackPopupMenu` 전 `SetTimer(TIMER_MENU)` → `WM_TIMER`에서 `SetMenuItemInfoW` + `FindWindowW(L"#32768")` `RedrawWindow`. 열린 팝업의 재그리기는 실기에서 확인 필요(T-2).
- Linux: 셸은 메뉴 열림/닫힘을 알려주지 않으므로 `AboutToShow`/`GetLayout` 후 30초를 "열려 있음"으로 보고 `ItemsPropertiesUpdated(a(ia{sv})a(ias))`를 1초마다 보낸다(작업 중일 때만).
- 검증: test_core(+8 검사) · linux-smoke(id 14 라벨 정규식) · macOS는 `NEXA_COFFEE_SHOW=menu`(status 버튼 `performClick:`) 훅을 넣었으나 전체 화면 창이 메뉴바를 가려 캡처하지 못했다 — 사용자 화면 확인 필요.

## 2차 — 상주 메모리 최소화 · 불필요 자원 검토 (사용자 요청)
### 측정(macOS · Intel)
- RSS 21.9 MB 중 **고유 메모리(phys_footprint)는 7.4 MB** — 나머지는 dyld 공유 캐시(AppKit 등 공유 페이지, 프로세스 소유 아님). 더티의 대부분은 AppKit 초기화 malloc(TINY 2.4 · SMALL 1.8 · MEDIUM 0.7 MB).
- 실험(x86_64 · 각 2회): `malloc_zone_pressure_relief` 7.37/7.69 MB(효과 없음 · 오차) · Prohibited 정책 7.29/7.52(효과 없음 → 창 제약만 생기므로 채택 안 함) · `MallocNanoZone=0` 7.67(없음) · **`MallocSpaceEfficient=1` 5.89 MB(−1.5 MB)** · relief+SpaceEfficient 5.76.
- 적용: 바이너리가 `MallocSpaceEfficient` 없으면 세팅 후 `execv` 재실행(어느 경로로 실행해도 적용) + 번들 `LSEnvironment`(보통 재실행 없음). relief는 무해해서 시작 직후 1회.
### 불필요 자원 검토
- 링크: macOS AppKit·IOKit(+Foundation·CoreFoundation·CoreGraphics·libobjc·libSystem은 AppKit 의존) · Windows kernel32/user32/shell32/gdi32 · Linux libc(musl 정적). 뺄 것 없음.
- 미사용 함수 제거: `cf_streq`(테스트만) · `cf_unit_color`(외부 미사용 → static) · `db_w_fd`·`db_r_bool`(미사용) · `DbMsg.fds`(fd 송신 안 함).
- 정적 자원: Windows `.rsrc` 15.8 KB가 exe 37.9 KB의 40% → ICO를 **PNG 프레임**(`tools/make-ico.py` · 3.7 KB)으로. macOS icns 152 → 62 KB(1024px 프레임 제거 · 번들만). 런타임에 읽는 자원은 Windows 클래스 아이콘뿐.
- 결과: Windows x64 exe 37,888 → 26,624 B · macOS 번들 실행 footprint 5,876 KB(bare 재실행 경로 5,616 KB) · 번들 276 KB(icns 포함).

## 4차 — Linux 실기(GNOME 50 · ubuntu-appindicators): 트레이 아이콘 안 보임 → 등록 경쟁 수정 (사용자 QA)
### 증상
- 릴리스 빌드 실행 → 워처에 등록됨(`RegisteredStatusNotifierItems`에 있음) · SNI/dbusmenu 속성 모두 정상 응답 · 확장 ACTIVE · 로그 무오류. 그런데 패널에 아이콘이 없다(포털 스크린샷으로 확인).
### 원인(`busctl monitor`로 잡음)
- GNOME AppIndicator 확장은 `RegisterStatusNotifierItem`을 받자마자 **응답을 주기 전에** 우리 항목에 `Properties.GetAll`을 보낸다(프록시 초기화). 우리는 `register_watcher()`에서 `db_call(..., NULL, NULL)`로 등록 응답을 동기 대기하면서 그 사이에 온 `GetAll`을 버렸다 → 셸의 프록시 초기화가 끝나지 않아 항목은 "등록됨"이지만 아이콘은 생성되지 않는다.
- 스모크가 못 잡은 이유: 스모크는 워처 없이 앱에 직접 호출하므로 이 순서가 재현되지 않는다(`RequestName` 쪽은 이미 `handle`을 넘기고 있었다).
### 수정
- `register_watcher()`의 `db_call`에 `handle`을 넘겨 대기 중 도착한 요청도 처리(1줄 + 전방 선언). 재캡처: `GetAll` 응답(35 KB)이 등록 응답보다 먼저 나가고 셸이 이어서 `GetLayout`까지 가져간다.
### 실기 결과(GNOME Wayland · VMware)
- 대기 아이콘 표시 ✓ · 12시간 클릭 → 동작 아이콘(초록 링 + "12") ✓ · 메뉴 라벨 "0일 11시간 59분 59초" ✓ · logind `sleep:idle:handle-lid-switch` block ✓ · 끄기 → "대기 중" · 억제 해제 ✓ · 설정 저장 `auto=0,0,0 / custom=0,1,0` ✓.
- **관찰**: GNOME 패널 아이콘은 16px인데 우리는 22·44px 픽스맵만 보내 확장이 22→16으로 축소한다 → 두 자리 숫자가 흐릿. 16px 프레임을 픽스맵 목록에 추가하면 코어 래스터라이저의 16px 기준 선명도를 그대로 쓸 수 있다(TODO).

## 5차 — 언어 선택 메뉴(English / 한국어 / 日本語 / 中文) · i18n (사용자 요청)
### 요청
자동 시작처럼 "언어 ▸" 서브메뉴를 두고 영어·한국어·일본어·중국어를 고르게. 메모리·실행 파일 크기는 최소로.
### 구현(코어)
- `CF_LANG_EN/KO/JA/ZH` · 루트에 `CF_ID_LANG`(16, 자동 시작 바로 아래) · 자식 `CF_ID_LANG0+lang`(30~33, 라디오) · 클릭 → `CF_ACT_LANG`(저장 + 메뉴·툴팁 전부 갱신).
- **크기 최소화**: 언어별 `const char *[]` 포인터 테이블(4×40×8 B + PIE 재배치) 대신 언어당 NUL로 구분한 문자열 블록 하나(`STR_EN[]`…) → id번째까지 걸어가는 `nth()`. 포인터는 언어당 1개. 메뉴를 열 때만 문구를 만드니 O(n) 걸음은 무시할 수준. 언어 이름·설정 태그도 같은 방식(`LANG_NAME` · `LANG_TAG`, lang*3).
- 툴팁 어순 일반화: en "2 hours left" · ko "2시간 남음" · **ja "残り2時間" · zh "剩余2小时"**(ja/zh는 '남음'이 앞). 예전 en 전용 `" sec "/" min "` 테이블은 없애고 남은 시간 라벨과 같은 단위 문구(S_SEC1.. = `CF_UNIT_*` 순서)를 재사용 → en 툴팁이 "5 min left" → "5 minutes left"로 바뀜.
- 설정 `lang=ko|ja|zh|en` — **메뉴에서 고른 뒤에만** 저장(`lang_set`). 안 골랐으면 OS 로케일 자동(로케일을 바꾸면 따라간다).
- `cf_lang_of("ko_KR.UTF-8" | "ja-JP" | "zh_CN")` — 3-OS의 로케일 판별 3중 코드를 코어 하나로.
### 플랫폼
- Windows: `PRIMARYLANGID` KOREAN/JAPANESE/CHINESE → lang. `CF_ACT_LANG` = 저장 + `job_tick()`/`show_idle()`로 툴팁 갱신(메뉴는 열 때 새로 만든다). 대화상자 문구는 이미 `cf_str`로 채운다. **빌드 미확인**(이 PC에 mingw 없음 — CI에서 확인 필요).
- macOS: `preferredLanguages` → `cf_lang_of`. `CF_ACT_LANG` = 저장 + `tickNow`/`showIdle`. **빌드 미확인**(Linux PC).
- Linux: `LC_ALL/LC_MESSAGES/LANG` → `cf_lang_of`. logind 억제 사유·화면보호기 사유를 `CF_STR_WHY/KEEPING`으로 코어에서. `CF_ACT_LANG` = 저장 + `LayoutUpdated` + `NewToolTip` + `NewTitle`. "대화창 도구 없음" 알림은 Linux 전용이라 linux.c에 4개 문자열 테이블로.
