라벨 `Manifest-Validation-Error`(09-13 09:14 · 13차에 고친 ManifestVersion 건) + **`Validation-Installation-Error`(09-13 22:13)** + `Needs-Author-Feedback`. 봇 문구는 "installing the application correctly"뿐이고 ADO 로그는 비공개라, **이 Windows PC에서 직접 재현**했다.

## 조치

### 1) PE 버전 리소스 추가 (`res/nexa-coffee.rc`)
버전 정보가 통째로 없는 **작고 · 서명 없고 · CRT도 없는** PE는 ML 휴리스틱의 고전적 오탐 대상이다. 서명이 없는 v1에서 할 수 있는 완화책이 이것이다.

- `VS_VERSION_INFO` 블록: CompanyName · FileDescription · FileVersion · InternalName · LegalCopyright · **OriginalFilename(아키텍처별)** · ProductName · ProductVersion.
- 숫자는 **VERSION 파일 하나에서** 온다 — rc에 손으로 적지 않는다. `Makefile`의 `RCDEF`(`$(subst ., ,$(VERSION))` → `-DCF_VER_MAJOR/MINOR/PATCH`)와 `build.bat`의 `for /f delims=.`가 같은 규약으로 넘긴다. `CF_ARCH64`로 OriginalFilename을 x64/x86으로 가른다.
- 문자열은 전처리기 stringize(`#`)로 만든다. **windres(gcc -E)는 당연히 되고, MSVC `rc.exe`도 지원하는지 이 PC에서 먼저 확인한 뒤** 채택했다(`rc.exe /dCF_VER_MAJOR=0 ... ` → 리소스에 "0.1.1" 박힘).
- 실측: `rc.exe`로 양쪽 아키텍처 컴파일 green(OriginalFilename이 각각 `nexa-coffee-x64.exe`/`-x86.exe`). **MSVC 전체 빌드 30,720 → 31,744 B**(+1,024) — 예산 64 KB의 절반 이하. 임베드 확인:
  `CompanyName=SosomLab · ProductName=Nexa Coffee · FileVersion=0.1.1 · OriginalFilename=nexa-coffee-x64.exe`
- mingw(windres) 크로스 빌드와 크기 예산은 이 PC에 mingw/make가 없어 **CI로 확인**(CLAUDE.md 규약).

### 2) choco `iconUrl` → jsDelivr (모더레이터 Requirement)
`https://cdn.jsdelivr.net/gh/SosomLab/nexa-coffee@v@VERSION@/packaging/branding/nexa-coffee-256.png` — 태그 고정. `@VERSION@`은 `render-manifests.sh`가 채우므로 치환 지점은 그대로 하나다. URL 200/image-png 확인.

### 3) `publish-windows-packages.yml`에 `channels` 입력
재제출은 보통 한 채널만 필요하다. 지금처럼 **choco만 다시 push**해야 하는데 `force=true`를 주면 winget 가드까지 풀려 **PR #433980과 중복되는 PR이 또 열린다**. `channels`(both·choco·winget)로 채널을 골라 그 사고를 막는다.

### 4) VERSION 0.1.0 → 0.1.1

### 5) winget 워크플로가 늘 죽던 진짜 이유 — `winget validate` 종료 코드 40
choco 재제출을 돌리다가 같은 워크플로의 winget 잡이 **`매니페스트 생성 + 검증` 단계에서** 죽는 것을 봤다(09-13 실패는 그 다음 `submit` 단계의 GitHub 연결 오류라 가려져 있었다).

```
Manifest validation succeeded with warnings.
Manifest Warning: Schema header not found. File: SosomLab.NexaCoffee.installer.yaml   (x3)
##[error]Process completed with exit code 40
```

`winget validate`는 경고가 있으면 **exit 40**으로 끝난다 — `set -euo pipefail`인 스텝이 거기서 죽는다. 우리 템플릿 세 개에 `# yaml-language-server: $schema=...` 헤더가 없었다(PR #433980의 매니페스트는 komac이 붙여 줘서 있었고, 그래서 그쪽만 통과했다).

이 PC에서 대조 확인:

| 스키마 헤더 있음(수정본) | "유효성 검사에 성공했습니다" · **exit 0** |
| 헤더만 제거 | 경고 3건 · **exit 40** |

→ 템플릿 세 개에 헤더 추가(`ManifestVersion`과 같은 1.12.0으로 유지).

## 남은 것 / 판단이 필요한 것

- choco 0.1.0은 모더레이터 요청대로 **지금 재제출**(사용자 확정). 0.1.1은 가드가 "직전 버전이 공개 피드에 없다"고 판단해 자동으로 건너뛴다 — 0.1.0 승인 뒤에 올린다.
- 근본 해결은 **코드 서명**이다(v1 범위 밖 · 문서에 명시돼 있다).
