### 결정(DR-16 보강)
| 채널 | 설치본 | 포터블 |
| --- | --- | --- |
| 릴리스 자산 | `nexa-coffee-<v>-windows-setup.exe`(그대로) | `nexa-coffee-<v>-windows-x64-portable.zip` · `-windows-x86-portable.zip`(이름 변경 · 전엔 `-windows-x64.zip`) |
| winget | `SosomLab.NexaCoffee` → nullsoft · `/S` · Scope user | **새 ID** `SosomLab.NexaCoffee.Portable` = zip |
| choco | `nexa-coffee` → `Install-ChocolateyPackage` · `/S` · 제거 스크립트 | **새 패키지** `nexa-coffee-portable` = 지금의 zip 방식 |
| brew · Linux | 무변경 | 무변경 |

- 기존 ID·패키지는 **버전별로 설치 유형이 바뀐다** — v0.1.3까지 포터블, 다음 태그부터 설치본. winget #436346(0.1.1 포터블)은 그대로 두고, 머지되면 다음 버전부터 같은 ID가 설치본(winget은 버전별 설치 유형 변경 허용).
- 새 ID·패키지(`.Portable` · `-portable`)는 첫 제출이라 커뮤니티 검수(며칠)를 다시 거친다.

### 릴리스 자산 실기
- Windows 3종 SHA256SUMS 일치 · setup 버전 리소스 0.1.4 · zip 내용 확인.
- setup `/S` 설치 → exe 0.1.4 → `uninstall.exe /S` 제거 ✅.
- ⚠️ **사고**: 이 PC엔 사용자가 설치본을 깔아 두었다(설치 폴더 존재 · `nexa-coffee.exe` 실행 중 · Run 값 있음). `/S` 업그레이드는 `.onInit` 덕에 Run 값을 유지했지만(설계대로), 이어진 제거 시험이 사용자 설치본을 지웠다. **복구**: 0.1.4 `/S /AUTOSTART=1` 재설치 → Run 값·시작 메뉴 바로가기 복원 → 실행. 설정(`%APPDATA%\nexa-coffee\config`)은 제거가 남기므로 그대로. 결과적으로 사용자 설치본은 0.1.4로 올라갔다.
- 교훈: 설치본 실기 전에 `%LOCALAPPDATA%\Programs\NexaCoffee`·Run 값·실행 중 프로세스를 확인하고, 있으면 제거 시험을 하지 않거나 끝에 원상 복구한다.
