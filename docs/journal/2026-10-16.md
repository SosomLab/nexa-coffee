### 검토 포인트(협업 세션 → 개발 세션)
- Windows: Run 값 이름이 설치본·앱에서 **글자 하나까지 같아야** 한다. 포터블 zip으로 켠 뒤 exe만 지우면 Run 값이 남는다(무해하지만 README에 적을지).
- Linux: deb/rpm 설치(`/usr/bin`)엔 `install.sh`가 없으니 앱이 직접 쓰는 `.desktop`의 `Exec`이 실제 경로를 가리켜야 한다. `install.sh`는 설치된 `.desktop`을 복사 + `X-GNOME-Autostart-enabled=true`를 붙인다 — 앱도 같은 결과를 내야 한다. 끄기 = 파일 삭제(`Hidden=true` 아님)로 맞추면 `uninstall.sh`·스모크와 단순하게 맞는다.
- winget/choco: 지금은 포터블 매니페스트 — 설치본으로 바꾸면 `InstallerType`·무인 설치 스위치가 바뀐다. 포터블을 유지할지 함께 결정(T-22).
- 크기 예산(Windows ≤ 64KB) — 레지스트리 코드 추가분 측정.
- 테스트: `test_core.c`(메뉴 트리·토글) · `linux-smoke.sh`(dbusmenu 항목 · `toggle-type`) · `test-install.sh`(앱이 쓴 `.desktop`을 `uninstall.sh`가 지우는지).

## 3차 — 언어 메뉴 "시스템 (OS 언어)" · 언어 변경 즉시 적용 (사용자 요청 · 개발 세션)

### 요청(사용자)
1. "nexa-sql·nexa-dir3처럼 언어 메뉴에 System (한국어)처럼 시스템 설정 언어가 보이게"
2. "지금 언어 변환이 안 되는 문제 확인"
3. "언어는 변경하면 바로 적용되어야 함"

### 조사 — "언어 변환이 안 된다"
- 새 빌드에서 명시 선택(日本語 클릭)은 설정 `lang=ja` 저장 + 메뉴가 즉시 일본어 — 캡처로 확인. **보고된 증상은 재현되지 않았다.**
- 유력한 원인: 한 번 언어를 고르면 `lang=`이 설정에 박혀 **OS 언어로 돌아갈 길이 없었다**. 이 PC의 사용자 설정에 `lang=en`이 있었고 OS는 한국어 — "OS를 따라 바뀌지 않는다"로 보였을 것. 아래 "시스템" 항목이 이 구멍을 막는다.
- 사용자가 다른 증상을 말하면 추가 조사.

### 구현(DR-13 보강)
| 항목 | 내용 |
| --- | --- |
| 메뉴 | 언어 ▸ 맨 위 라디오 `CF_ID_LANG_SYS = 29` — 라벨 = "System/시스템/システム/系统" + " (OS 표시 언어 이름)"(nexa-sql `settings.rs` "괄호 = OS 설정값" 기준) · 서브메뉴 5항목 |
| 고를 때 | `lang_set = 0` → 설정에서 `lang=` 제거 → 즉시 OS 언어 |
| 체크 | 자동 모드면 "시스템"만 체크 — 명시 항목은 OS 언어와 같아도 체크 안 함 |
| OS 언어 변경 | `CfApp.os_lang` + `cf_set_os_lang()` — Windows `WM_SETTINGCHANGE` · macOS `NSCurrentLocaleDidChangeNotification` → 자동 모드면 툴팁 즉시 · 메뉴는 다음 열 때 |
| Linux | `LANG` 환경 변수 → 시작 시 고정(**알려진 한계** · 다시 실행해야 반영) |

### 검증
- `test_core` green — 서브메뉴 5항목 · 라벨 4언어 · `os_lang` 변경 · `lang=` 제거.
- `linux-smoke.sh` 절 추가 — CI 대기.
- Windows 실기 ✅ — 29 클릭 → 설정의 `lang=en` 제거 · 메뉴 즉시 한국어 · 서브메뉴 "● 시스템 (한국어)" 캡처. 시험 뒤 사용자 설정은 시험 전 상태(`lang=en`)로 복원.

### 남은 것
- macOS: OS 언어 변경 → 툴팁 즉시 반영 실기(T-11 macOS와 함께).
- 사용자: 이 PC 설정에 `lang=en`이 남아 있다 — 메뉴에서 "시스템 (한국어)"를 고르면 한국어로 돌아온다.
