# 2026-11-07 — macOS 잠긴 화면 반복 깨우기 · loginwindow 창 누적 수정 (사용자 보고 11-05·11-07 · macOS · 두 세션 협업)

## 1차 — 원인 분석 · 수정 방향(DR-17)

### 보고(사용자)
잠가 둔 맥이 밤새 화면을 켰다 껐다 반복하고, 아침에 마우스가 느리다. 깨운 프로세스는 nexa-coffee.

| 구간 | 화면 켜짐·꺼짐 | loginwindow 창 | 회당 창 |
| --- | --- | --- | --- |
| 11-05 01:25~08:45 | 약 880회 | 2,488개 | 약 2.8개 |
| 11-07 00:57~11:38 | 1,282회 | 3,799개 | 약 3.0개 |

- 깨운 주체: nexa-coffee(`UserIsActive` 1,891회).
- 결과: WindowServer CPU 79~102% → 마우스 응답 지연.

### 원인(코드)
- `src/plat/mac.m`의 `declareActivity`가 작업 중 30초마다 `IOPMAssertionDeclareUserActivity(kIOPMUserActiveLocal)`를 **조건 없이** 호출한다(목적: 화면보호기 유휴 타이머 재설정 · D-1).
- 이 API는 꺼진 화면을 **켠다**. 화면이 잠겨 꺼진 뒤에도 30초마다 켜짐 → 잠금 화면(loginwindow)이 매번 다시 그려지며 창이 쌓임 → WindowServer 부하.
- 시스템·화면 어설션(`PreventUserIdleSystemSleep` · `PreventUserIdleDisplaySleep`)은 원인이 아니다. 유휴로 꺼지는 것만 막고 꺼진 화면을 켜지 않는다.

### 수정 방향(DR-17 · 개발 세션)
- 화면이 잠겼거나(`CGSessionCopyCurrentDictionary`의 `CGSSessionScreenIsLocked` = true · 잠기지 않았을 땐 키 자체가 없음 — 이 맥 실측) 화면이 꺼진 동안(`CGDisplayIsAsleep`)에는 사용자 활동 선언을 건너뛴다.
- 시스템·화면 어설션은 그대로 둔다 — 절전 방지 목적 유지 · 잠금 해제 직후 화면이 곧바로 꺼지는 것 방지.
- D-1(30초 사용자 활동 선언으로 화면보호기가 막히는가) 종결 → DR-17.
- 브랜치 `fix/mac-wake-when-locked`.

### 검토(협업 세션 → 개발 세션)
| 질문 | 판단 |
| --- | --- |
| ① 잠금 중 화면 어설션도 내릴까 | **유지**. 어설션은 꺼진 화면을 켜지 않는다. 다시 켜는 것은 사용자 활동 선언뿐 |
| ② Windows·Linux도 같은 증상인가 | **아니다**. Windows는 `job_start`에서 `SetThreadExecutionState(ES_CONTINUOUS\|…)`를 한 번 거는 상태 유지형 · Linux는 `ScreenSaver.Inhibit` 쿠키 + logind fd 보유형. 주기적으로 활동을 주입하는 곳은 macOS `declareActivity` 하나 |
| ③ 0.1.5 릴리스 | **필요**. 상주하는 동안 머신 전체를 느리게 하는 결함 · brew 사용자는 업그레이드로만 고친다 |

구현 주의점(전달함):
- `CGSessionCopyCurrentDictionary` 반환값은 `CFRelease` 필수(30초마다 누수) · NULL이면 건너뛴다.
- 빠른 사용자 전환으로 세션이 콘솔에서 빠졌을 때(`kCGSessionOnConsoleKey` = false)도 건너뛴다.
- `CGDisplayIsAsleep(CGMainDisplayID())`는 주 화면 기준 — 외장 모니터 구성에서 한 번 확인.
- `declareActivity`가 매번 새 id로 선언한다 → 받은 id를 보관해 넘기면 같은 어설션을 갱신한다. `pmset -g assertions`로 누적 여부 확인.
- 검증: 작업 시작 → 잠금 → 화면 꺼짐 후 몇 분 → `pmset -g log`에 화면 켜짐이 늘지 않는지 · 잠금 해제 후 화면보호기가 여전히 막히는지.
